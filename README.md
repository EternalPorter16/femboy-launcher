## 📥 Установка

1. Открой **[сайт лаунчера — скачать](https://femboylauncher.ru/#download)**.
2. Скачай **`FemboyLauncher-Setup-<версия>.exe`** (обновляется сам) или **`FemboyLauncher-Portable-<версия>.exe`** (без установки).
3. Если Windows показывает предупреждение или файл не открывается, посмотри **[помощь с первым запуском](https://femboylauncher.ru/#help)**.

Java, Minecraft, загрузчики и моды лаунчер скачает сам.

## ✨ Что умеет

- **Сборки (instances)**: у каждой своя папка с мирами, модами и настройками, своя иконка, цвет и память.
- **Ванилла, Fabric, Quilt, Forge и NeoForge**: загрузчик ставится сам. Forge и NeoForge ставятся официальным установщиком в тихом режиме при первом запуске сборки (1–3 минуты). Поддерживается Forge с версии 1.12.2.
- **Моды с Modrinth**: поиск под версию и загрузчик сборки, установка в один клик вместе с обязательными зависимостями (например, Fabric API), проверка хэшей.
- **Модпаки с Modrinth**: `.mrpack` ставится как новая сборка вместе с модами и настройками. В установленной версии (не portable) двойной щелчок по `.mrpack` в Проводнике открывает лаунчер (или уже открытый) и спрашивает «Поставить модпак «…» как новую сборку?»; отказ ничего не ставит. Привязку типа файла записывает установщик, при удалении программы она убирается.
- **Коллекция Modrinth**: кнопка «Коллекция» на странице «Моды» (или Ctrl+K): вставляешь ссылку на коллекцию с modrinth.com, лаунчер показывает её моды, ресурспаки и шейдеры и помечает, что подойдёт выбранной сборке (или версии игры с загрузчиком для новой сборки), а что нет и почему: нет под эту версию, нет под этот загрузчик, модпак ставится отдельно из «Модпаков». Для новой сборки сразу подсказывает версию и загрузчик, под которые подходит больше всего проектов. Выбранное ставится обычным путём (версия под игру и загрузчик, обязательные зависимости, проверка хэшей); что не вышло, перечислено в итоге с причиной. В существующую сборку перед установкой делается точка восстановления, «Отменить» останавливает всё сразу, а новая сборка, в которую ничего не поставилось, не остаётся пустой. Закрытые (приватные) коллекции лаунчер не видит; больше 300 проектов за раз не берёт.
- **CurseForge**: моды и модпаки, нужен личный бесплатный API-ключ (Настройки → CurseForge, ключ берётся на console.curseforge.com). Обычные ключи не дают права на **поиск** (CurseForge открывает его только одобренным лаунчерам), поэтому с таким ключом ставь по **Project ID** со страницы мода: вставь ID в поле поиска. Моды, авторы которых запретили скачивание из сторонних лаунчеров, лаунчер не качает, а даёт ссылку на них.
- **Установленные моды**: включение и выключение без удаления, удаление, открытие папки.
- **Обновление модов**: проверка и «обновить все». Modrinth ищет по хэшу файла, поэтому находит обновления даже для модов, поставленных вручную. Кнопка **📌** у мода закрепляет его версию: «Обновить моды» такой мод пропускает (метка «закреплён» в списке, в окне обновлений сказано, сколько модов закреплено); повторное нажатие открепляет. Закрепление хранится в `mods-meta.json` сборки и уходит вместе с модом при удалении.
- **Ресурспаки и шейдеры** с Modrinth/CurseForge; для шейдеров сам ставится Iris (или Oculus на Forge).
- **Фильтры поиска**: категории и сортировка.
- **«Оптимизация»**: окно со списком, что подходит сборке. «Основа» отмечена сама: Sodium, Lithium, FerriteCore, Entity Culling, ImmediatelyFast, ModernFix; дополнительно по желанию Dynamic FPS, More Culling, Sodium Extra, Ixeris, ScalableLux и другие. На Forge вместо Sodium ставится Embeddium; чего для загрузчика и версии нет, того не предлагается (с причиной).
- **Видеокарта для игры**: на ноутбуке с двумя видеокартами Windows часто запускает Minecraft на встроенной. Лаунчер один раз спросит и, если согласишься, пропишет Java «высокую производительность» в «Параметрах графики» Windows; переключатель в Настройках → Игра и Java возвращает всё как было.
- **Графика одной кнопкой** (вкладка «Ещё» в окне сборки): «Экономная», «Сбалансированная» или «Красивая» подкручивают дальность прорисовки, частицы, FPS и ещё несколько настроек в `options.txt`; клавиши и язык не трогаются, «Вернуть как было» возвращает прежние значения.
- **Советы по скорости**: значок «⚡ N советов» на карточке сборки подсказывает, что поправить (мало или слишком много памяти, видеокарта на ноутбуке, нет модов для скорости, тяжёлая дальность прорисовки, шейдеры на скромном ПК), и исправляет в один клик.
- **Не нагружает компьютер**: когда лаунчер не нужен (окно не в фокусе или ничего не трогали), анимации замирают и процессор почти не работает. «Экономный режим» (сам включается на батарее) убирает лепестки, светлячков и звёзды совсем. Шрифты лежат внутри, лаунчер не ждёт интернет при запуске.
- **Импорт и экспорт сборок**: `.mrpack`, zip CurseForge, сборки Prism/MultiMC; экспорт в `.mrpack` (моды с Modrinth уходят ссылками, файл лёгкий); копия сборки.
- **Перенос из других лаунчеров**: сборки, миры, моды и паки из **Legacy Launcher (TL Legacy)**, TLauncher, официального лаунчера, Prism/PolyMC/MultiMC, CurseForge, Modrinth App, ATLauncher и GDLauncher. Лаунчер ищет их сам, в том числе портативные копии на рабочем столе, в «Загрузках» и на других дисках, а также HMCL, PCL и другие, которых нет в списке, по устройству папок. При запуске он один раз предлагает перенести найденное (выключается в Настройках → Место и переезд). У Legacy Launcher учитывается папка игры из его настроек (`%APPDATA%\.tlauncher\legacy.properties`) и сборки из подпапок `home/`. Всё копируется или подключается «на месте», старые лаунчеры не меняются; потом можно освободить место от старых копий.
- **Помощник при вылете**: понятная причина (память, Java, нет Fabric API, несовместимые/задвоенные моды, драйвер видеокарты), отчёт о вылете и кнопка «починить», где это возможно. Если у сборки уже был удачный запуск, окно вылета называет, **что изменилось с него**: какие моды добавлены, убраны, изменены, включены или выключены (по именам файлов) и не сменились ли версия игры, загрузчик, его версия или модпак, и предлагает **«Откатить на последний удачный запуск»** одним щелчком (нынешнее состояние перед этим сохраняется, откат можно отменить). Если моды и версии те же, окно так и говорит и не придумывает виновников; настройки (`config`) в сравнение не входят, потому что игра переписывает их сама. Удачным считается запуск, который закончился обычным выходом (код 0), не был остановлен лаунчером, шёл дольше трёх минут, и моды за время игры не менялись (новый мод в игру не попал бы); во время поиска мода-виновника такие точки не делаются.
- **Выбор версии загрузчика** (окно «Изменить сборку» → «Версия загрузчика»): для Fabric, Quilt, Forge и NeoForge показывается список версий под выбранную версию игры (новые сверху, у Forge отмечена «рекомендуемая», пре-релизы прячутся за галочкой). Зачем: после первого запуска лаунчер запоминает версию загрузчика в сборке, чтобы новый выход не сломал моды, и раньше её нельзя было ни обновить, ни откатить. Теперь можно взять свежую (её требует мод) или старую (её требует модпак), либо выбрать «Последняя стабильная», и она поставится при следующем запуске. Для Fabric и Quilt окно сразу предупреждает, каким модам выбранная версия не подходит (по их описаниям). Если версии у загрузчика нет, лаунчер говорит это прямо и отправляет в настройки сборки. Выбранная версия видна в подсказке на значке загрузчика.
- **Поиск мода-виновника** (кнопка в окне вылета, «Ещё → 🔎 Найти виновника» или Ctrl+K): если игра вылетает или глючит, а из-за какого мода, непонятно, лаунчер ищет его делением пополам. Сначала запускает игру без модов (чтобы не обвинять моды зря), потом включает половину модов вместе с нужными им библиотеками (чтобы игра падала из-за виновника, а не из-за «не хватает мода»), и после каждого запуска спрашивает, повторилась ли проблема (вылет засчитывается сам). Для сборки из 40 модов хватает около 8 запусков. Если в отчёте о вылете есть строка «Suspected Mods», подозреваемые проверяются первыми (иногда хватает двух запусков). Виноват не один мод, а сочетание — находятся оба; проблема есть и без модов или только при всех сразу — лаунчер так и скажет. Перед началом сохраняется точка восстановления, а состояние поиска лежит в папке сборки (`bisect.json`): поиск можно продолжить после перезапуска лаунчера, а все моды в любой момент вернуть как были. Пока поиск идёт, кнопка «Играть» открывает окно поиска, а не запускает игру с частью модов.
- **Миры и скриншоты**: список миров, резервная копия в zip, удаление; галерея скриншотов. Кнопка **«Играть»** у мира запускает игру и сразу заходит в этот мир (Minecraft 1.20 и новее: старые версии так не умеют, поэтому у них кнопки нет).
- **Серверы**: список серверов сборки с пингом (онлайн, игроки, задержка); «Зайти» запускает игру и сразу подключается.
- **Несколько сборок одновременно.**
- **Настройки сборки**: своя память, размер окна или полный экран, своя Java и аргументы JVM.
- **Зеркала загрузок**: если серверы Mojang/Forge/Fabric тормозят, лаунчер переключается на зеркало BMCLAPI (файлы проверяются по хэшам); можно выбрать «только официальные».
- **Прокси и VPN**: лаунчер ходит в сеть стеком Chromium, как браузер, поэтому понимает системный прокси, PAC-скрипты и сертификаты Windows; вход Microsoft идёт тем же путём. Свой прокси (`http://адрес:порт` или `socks5://адрес:порт`) вписывается в Настройки → Игра и Java → «Запуск и загрузки». Кнопка **«Проверить связь»** стучится к девяти серверам лаунчера (Mojang, Modrinth, CurseForge, Fabric, Microsoft, зеркало, обновления), показывает время ответа, причину отказа и подсказку, что делать. У любого запроса есть таймаут, молчащий прокси не повесит лаунчер. Игре лаунчер отдаёт тот же прокси флагами Java (если он отвечает): иначе моды вроде e4mc, которые сами ходят в сеть, не выходят наружу, когда доступ есть только через VPN-прокси. Если эти флаги мешают игре или моду, их можно выключить: Настройки → «Игра и Java» → «Запуск и загрузки» → «Передавать игре прокси лаунчера» (игра тогда идёт в сеть напрямую, в консоли об этом строка).
- **Играть с другом** (Ещё → «💞 Играть с другом»): ставит бесплатный мод e4mc, который открывает мир в интернет без настройки роутера; адрес вида `xxx.e4mc.link` лаунчер ловит в логе игры и сам копирует. **Список друзей** в этом окне один на все сборки (до 50 человек, лежит в `launcher.json`): у каждого друга галочка «пустить в этот мир» и пометка «с лицензией» / «без лицензии» (по нажатию меняется); при добавлении лицензию проверяет Mojang, а у друга с лицензией лаунчер запоминает настоящий UUID, чтобы у него остались вещи и скин. Ники, которые окно раньше помнило у каждой сборки отдельно, один раз переносятся в общий список. В `whitelist.json` записываются только друзья с галочкой, с верным UUID (для друга без лицензии важен регистр букв ника), и только когда игру запускают кнопкой «Играть ♡» из этого окна (или нажимают «Подготовить»): обычная кнопка «Играть» друзей не записывает. **Белый список живёт один мир**: когда мир, открытый для друзей, закрывается (по строке `Stopping server` в логе после «Published LAN server» / «Started serving»), и когда закрывается игра, лаунчер очищает `whitelist.json` (прежний непустой список остаётся рядом в `whitelist.json.bak`) и говорит об этом; в следующий мир друзей записывает заново «Играть ♡» или «Подготовить» (сами друзья и галочки остаются в списке, лишним галочку снимают). Окно с адресом мира показывает, кто записан на самом деле, и кто из друзей сейчас в мире: лаунчер читает «зашёл» и «вышел» из лога игры, говорит об этом уведомлением и строкой в консоли (о хозяине мира и о закрытии мира молчит). **Прямые адреса для входа по сети и VPN:** лаунчер берёт порт открытого мира из строки лога (`Published LAN server on port N`) и список адаптеров Windows и показывает адреса вида `192.168.1.5:61223` для друга в той же сети или в одной VPN-комнате (Radmin VPN, Hamachi, ZeroTier, Tailscale; адаптеры виртуальных машин, WSL и туннелей прокси пропускаются, IPv6 идёт последним) — в консоли и под адресом e4mc, а если e4mc не вышел, отдельным окном «Мир открыт по сети». Только показ: лаунчер ничего не открывает и не настраивает. **Перед тем как мир откроют для друзей по сети, лаунчер сохраняет его автокопию** (настройка «Копия мира перед открытием для друзей», включена по умолчанию): открытый мир определяется по замку `session.lock`, который игра создаёт при открытии мира; копия того же мира чаще раза в полчаса не делается, старые автокопии подчищаются по общей настройке («сколько хранить»). Если в гостях что-то сломают, мир можно вернуть во вкладке «Миры». Выключается в Настройки → «Играть с другом». Кнопка **«Проверить»** в этом окне за несколько секунд проверяет то, от чего зависит открытие мира, и называет, что мешает: стоят ли и включены ли моды e4mc и LAN World Plug-n-Play; каким путём игра выходит в сеть (напрямую или через системный HTTP-прокси, который лаунчер передаёт ей флагами Java); отвечает ли сервер адресов e4mc именно этим путём; доходит ли до ретранслятора UDP (один QUIC-пакет); не включён ли в мире «Белый список» без ников друзей, цел ли `whitelist.json`. Проверка ничего не ставит и не меняет; итог — «всё готово / есть замечания / не получится», отчёт копируется кнопкой.
- **Войти к другу и код сборки** (Ещё → «🚪 Войти к другу» или Ctrl+K): хозяин копирует **код сборки** кнопкой «📋 Код сборки» в окне «Играть с другом» или «📋 Адрес и код сборки» в окне с адресом мира (адрес и код одним сообщением). Код — короткий текст вида `FLM1:1318:…`: версия игры, загрузчик и id версий Modrinth всех включённых модов, а для модов не с Modrinth ещё имя файла и начало отпечатка; ни путей, ни названия сборки, ни аккаунтов. Он помещается в одно сообщение чата (около 600 знаков на 60 модов, 1300 на 150, 1900 на 220). Гость вставляет сообщение друга **целиком** в окно «Войти к другу»: лаунчер сам находит в нём адрес (e4mc, IP с портом, IPv6 или обычное имя) и код (по заголовку и длине, поэтому код переживает переносы строк, кавычки и любые слова вокруг; обрезанный или повреждённый код объясняется понятно) и сверяет моды с выбранной сборкой: **совпало**, **включу** (мод есть, но выключен), **заменю** (другая версия), **поставлю** (нет), **нужны файлы от друга** (мод не с Modrinth, его версию удалили с Modrinth или файл с тем же именем другой) и **лишние** (есть у тебя, нет у друга: обычно не мешают). Если версия игры или загрузчик не совпадают (Quilt на модах Fabric — не помеха), об этом сказано первым делом, а установка в эту сборку закрыта: подходящую сборку лаунчер выбирает сам, а если её нет, предлагает «Новая сборка как у друга» (создаёт её с версией игры и загрузчиком хозяина). «Поставить как у друга» скачивает точные версии с Modrinth с проверкой хэша; перед правкой существующей сборки сохраняется точка восстановления («Перед установкой модов друга»), сбой отдельного мода не останавливает остальные и показан в окне, чужой файл с тем же именем не перезаписывается, а выключенная копия нужной версии при замене не оставляет дубля. «Зайти» запускает выбранную сборку сразу на адрес из сообщения (если сборка уже запущена, лаунчер просит закрыть игру, а не закрывает её сам); без кода в сообщении окно работает как «зайти по адресу». Для сборки кода и сверки нужна связь с Modrinth.
- **Следовать за сборкой друга** (галочка в окне «Войти к другу»): сборка запоминает, что она «как у друга» (отметка «👥 как у друга» на карточке, по щелчку открывается то же окно). Друг обновил моды и прислал новый код, вставляешь его сюда: лаунчер показывает разницу и по «Сделать как у друга» ставит и заменяет нужное, а моды, которых у друга нет, **отключает** (не удаляет: включить обратно можно в «Моды» или откатом из точки восстановления, она сохраняется перед правкой). Код передаётся только текстом: ничего не скачивается по ссылке и ничего не проверяется по расписанию, обновление запускает человек. Для новой сборки «как у друга» галочка включена сама. Работает на `core/modcode.js` (`execute` с `follow`, `markFollow`, поле `follow` в файле сборки).
- **Корзина сборок**: «Удалить» не стирает сборку, а переносит её папку в `trash\` рядом с данными (мгновенно, место не занимается); на главной появляется кнопка «Корзина», где сборку можно вернуть целиком (миры, моды, настройки) или стереть навсегда (второй клик). Когда лаунчер закрывается, корзина очищается: папка переименовывается, а стирает её отдельный процесс, так что окно не ждёт. После аварийного закрытия корзина остаётся и видна при следующем запуске. Точки восстановления и облачная копия удаляются только вместе с окончательным удалением, а синхронизация не возвращает сборку из корзины.
- **Копирование ника**: кнопка «Копировать ник» у каждого аккаунта, правый клик по своему профилю внизу слева и действие «Скопировать мой ник» в Ctrl+K: ник нужен друзьям, чтобы записать тебя в свой белый список.
- **Запуск без интернета**: список версий Mojang хранится на диске (`cache/version_manifest_v2.json`), профили версий и клиент берутся из папки игры, поэтому то, что уже скачано, запускается без связи. Если нет связи только с Microsoft, игра запускается без входа в аккаунт (с тем же ником и UUID: одиночная игра работает, на серверы с лицензией не зайти), а лаунчер сообщает об этом. Настоящий отказ Microsoft (отозванный вход, нет покупки) остаётся ошибкой.
- **Точки восстановления** (Ещё → Точки восстановления): перед обновлением модов, обновлением модпака, «Оптимизацией» и установкой недостающих модов лаунчер сам сохраняет снимок: моды (жёсткими ссылками, поэтому мгновенно и почти без лишнего места), папку `config`, версию загрузчика и записи о том, что откуда поставлено. «Вернуть» откатывает всё это (миры, скриншоты и `options.txt` не трогаются); нынешнее состояние перед откатом тоже сохраняется, так что откат можно отменить. Если с прошлой точки ничего не менялось, новая не создаётся; хранятся 8 последних автоматических и до 20 всего, точки «вручную» не чистятся сами. Особая точка **«Последний удачный запуск»** (📌, закреплена сверху списка) делается и обновляется сама после каждого нормального выхода из игры: она одна на сборку, в эти лимиты не входит, обычные точки «Перед обновлением…» её не заменяют (и она их), а прежняя удачная точка удаляется только после того, как новая записана целиком. С неё сравнивает окно вылета (см. «Помощник при вылете»).
- **Перенос сборки на новую версию Minecraft** (Ещё → «🚀 На новую версию» или Ctrl+K): лаунчер делает **копию** сборки на выбранной версии (предлагаются релизы новее нынешней) и подбирает версии модов. Перед созданием копии окно показывает, что **обновится**, что **подойдёт как есть** (в том числе мод не с Modrinth, если сам заявляет поддержку новой версии), чего **нет под новую версию** (в копию не попадёт, но остаётся в отчёте) и что **неопознано** (переедет выключенным, чтобы решить самому). Моды ищутся на Modrinth по хэшу файла одним запросом, а те, что лаунчер ставил с CurseForge, по id проекта (нужен ключ). Библиотеки, нужные новым версиям модов, добавляются сами, загрузчик подбирается под новую игру. Настройки, ресурспаки, шейдеры, серверы и (по галочке) миры переезжают в копию; старая сборка не меняется ни на байт, а миры в копии игра обновит сама. Не скачавшийся мод не останавливает перенос, а попадает в отчёт; «Отменить» или сбой удаляют копию целиком. Не хватает места на диске — об этом сказано до копирования. Отчёт лежит в папке копии (`migration.json`) и открывается кнопкой «Отчёт о переносе» в «Ещё».
- **«Пора на новую версию?»** (значок на карточке сборки): раз в сутки лаунчер в фоне (первый раз через полминуты после запуска, потом по очереди, с паузой между сборками и без сообщений об ошибках) считает, сколько модов каждой сборки уже вышло под **самую свежую версию Minecraft**. Если готова хотя бы половина, на карточке появляется значок «🚀 1.21.9: готовы 38 из 40 модов»; по нему открывается «На новую версию» сразу с этой версией. Подсчёт тот же, что в переносе (обновятся + подойдут как есть), но лёгкий: два запроса к Modrinth на сборку, без названий, библиотек, миров, Java и CurseForge (моды оттуда считаются неопознанными); ничего не скачивается и не меняется. Проверяются только сборки с модами на обычном релизе старше самого свежего (ванильные, снапшоты и сборки уже на свежей версии пропускаются). Итог лежит в `readiness.json` рядом с настройками (не в папке сборки), пропадает при смене модов или версии сборки и не показывается, если ему больше трёх суток; после ошибки Modrinth сборку не спрашивают раньше чем через 6 часов, а без связи обход сразу останавливается. На Modrinth уходят хэши файлов модов, как и при проверке обновлений. Выключается: Настройки → «Игра и Java» → «Запуск и загрузки» → «Подсказывать, когда моды готовы к новой версии Minecraft».
- **«Вышли обновления модов» и «Что нового» в окне обновлений** (значок на карточке сборки): раз в сутки лаунчер в фоне (первый раз через три четверти минуты после запуска, по очереди, с паузой между сборками, без сообщений об ошибках) спрашивает Modrinth, вышли ли новые версии модов сборки, и на карточке рядом с советами появляется значок «⬆ 3 обновления модов» (в подсказке названия: «Sodium, Iris, Lithium и ещё 2»). Проверка лёгкая: один запрос по хэшам файлов (закреплённые версии не спрашиваются), ничего не скачивается и ничего не ставится само; CurseForge в фоне не опрашивается. По щелчку открывается обычное окно «Обновить моды»: оно, как и раньше, сверяет новые версии с остальными модами, а теперь под каждым обновлением есть сворачиваемое **«Что нового»**: описание версии с Modrinth простым текстом (без разметки, ссылок и картинок, списки с точками, до 14 строк и 700 знаков). Число на значке после этого окна совпадает с числом в нём, а после установки обновлений значок перепроверяется. Итог лежит в `modwatch.json` рядом с настройками (не в папке сборки), пропадает при смене модов или версии сборки и не показывается, если ему больше трёх суток; после ошибки Modrinth сборку не спрашивают раньше чем через 6 часов, без связи обход останавливается. На Modrinth уходят хэши файлов модов, как и при ручной проверке. Выключается: Настройки → «Игра и Java» → «Запуск и загрузки» → «Подсказывать, когда вышли обновления модов».
- **Прогресс на значке в панели задач**: загрузки (моды, модпаки, обновления) и подготовка сборки к запуску (Java, файлы игры, загрузчик) показываются зелёной полоской на значке лаунчера, даже когда окно свёрнуто; у шагов без процентов («Проверяю файлы…») полоска бегущая. Если готовятся несколько дел сразу, видно то, что обновилось последним. Полоска гаснет, когда дело кончилось, отменено или сорвалось, и сразу, как только игра пошла.
- **Список переходов на значке** (правый щелчок по значку лаунчера в панели задач): шесть последних сборок, запуск одним щелчком (то же, что ярлык сборки: `--launch=<id>`; в Windows с выключенными «недавними элементами» те же ссылки лежат среди «Задач»). Обновляется после изменений сборок, после игры и при старте. Работает в установленной и portable-версии; при запуске из исходников и в проверках список переходов не трогается.
- **Вход через Ely.by**: логин (ник или почта), пароль и, если включена двухфакторная защита, код из приложения (сервер Ely.by принимает его в конце пароля через двоеточие). Пароль нигде не сохраняется: остаётся токен, зашифрованный средствами Windows, а перед игрой он проверяется и при необходимости обновляется. В игру Ely.by подключается java-агентом authlib-injector с настройками, сохранёнными на диске (поэтому игра стартует и без интернета). Скин и плащ меняются на ely.by, в лаунчере есть кнопка «Обновить скин». При выходе из аккаунта токен отзывается на сервере.
- **Выбор Java**: «Найти Java» ищет установленные Java (папки Program Files, JAVA_HOME, PATH, `.jdks`, Java лаунчера и официального лаунчера Minecraft; версия берётся из файла `release`), «Выбрать файл…» и «Авто». Рядом сразу видно, подходит ли выбранная Java игре: слишком старая — ошибка с советом (до запуска, а не вылет посреди загрузки), слишком новая или 32-битная — предупреждение.
- **Происхождение модов**: на вкладке «Установленные» моды, которых нет на Modrinth (ищем по хэшу файла, как при проверке обновлений) и которые лаунчер сам не ставил, помечаются «неизвестный источник» (результат запоминается, неизвестные перепроверяются раз в неделю). Чужие jar-файлы бывают вредоносными, поэтому лучше знать, что лежит в папке.
- **Отчёт для поддержки** (Настройки → О лаунчере): ZIP с версиями, железом, Java, настройками, проверкой связи, консолью и логом лаунчера и (для выбранной сборки) списком модов, `latest.log`, свежими отчётами о вылете и `hs_err`. Паролей, токенов, ключа CurseForge, ников аккаунтов, имени пользователя Windows в путях, почты и адресов серверов с портом в нём нет. Файл никуда не отправляется.
- **Поделиться логом**: кнопка в консоли и в окне вылета отправляет лог на mclo.gs (после подтверждения; текст перед этим очищается так же, как для отчёта) и копирует ссылку в буфер обмена.
- **Починить файлы игры** (вкладка «Ещё» у сборки): заново сверяет по хэшам клиент и профиль версии, профиль Fabric/Quilt, библиотеки и **все** ресурсы игры (обычный запуск проверяет ресурсы только по наличию и размеру) и скачивает то, что повреждено или пропало; итог показывает, что проверено и сколько файлов пришлось скачать заново. Миры, моды и настройки не трогает; Forge и NeoForge ставит свой установщик при запуске, их файлы здесь не проверяются. Пока идёт любая игра, починка не запускается (библиотеки и ресурсы общие).
- **Время в игре** (Настройки → «Котик и награды»): лаунчер записывает каждую сессию (начало, конец, сборка; не дольше 400 дней, короче пяти секунд не пишутся) и показывает неделю по дням столбиками, сборки за 30 дней полосками, всего, самую долгую игру и «считаю с какого дня». Журнал лежит отдельным файлом `playlog.json` в папке данных; общее время сборки считается как раньше. Журнал ведётся с этой версии, поэтому прошлые игры в нём не видны.
- **«Итоги игры»: картинка за неделю или месяц** (кнопка «🖼️ Итоги недели и месяца» в карточке «Время в игре» и Ctrl+K): лаунчер рисует карточку 1080×1350 с котиком в твоём наряде и цветами выбранной темы: сколько играл (неделя — семь дней, месяц — тридцать, последний день — сегодня), насколько больше или меньше, чем в прошлый такой же срок, столбики по дням, число игровых сессий, дни в игре, самая долгая игра, лучший день, любимая сборка с долей времени и реплика котика (она зависит от того, много ли играл). Срок переключается («Неделя» / «Месяц»), названия сборок можно скрыть галочкой, если картинку покажешь друзьям (выбор запоминается). «Сохранить картинку» открывает окно выбора места (PNG, имя вроде «Итоги недели 2026-10-30.png») и показывает файл в папке, «Скопировать» кладёт картинку в буфер обмена только по нажатию. Картинка собирается на компьютере и никуда не отправляется; подписи и дата на русском или английском по языку лаунчера. Данные берутся из того же журнала `playlog.json`.
- **Место на диске перед загрузкой**: перед большой докачкой (клиент игры, библиотеки, ресурсы) лаунчер смотрит свободное место и, если его не хватает, сразу говорит, сколько нужно и сколько есть (с подсказкой «Настройки → Место и переезд → Освободить место»), а не падает посреди скачивания. Если узнать место не вышло, загрузке это не мешает.
- **Консоль и логи игры**: в консоли есть поиск (строки без искомого прячутся, регистр не важен, показано «Найдено: N из M») и галочка «только ошибки»; новые строки подчиняются тому же фильтру. Во вкладке «Ещё» у сборки кнопки «📜 Лог игры» (открывает `latest.log` последнего запуска в программе для текстов) и «📂 Папка логов» (`<папка сборки>\logs`).
- **Быстрый поиск (Ctrl+K)**: страницы, разделы настроек, сборки («Играть: …»), действия (новая сборка, импорт, проверка связи, тема, язык, масштаб, вход в аккаунты…) и моды выбранной сборки; работает и на русской раскладке, ищет и по-английски в английском интерфейсе. Кнопка поиска есть и в заголовке окна.
- **Масштаб интерфейса** (Настройки → Оформление): 90–150%, а также Ctrl + «+», «−», «0». Окно при этом подрастает до размера, которого макету достаточно, но не больше экрана.
- **Настоящий portable**: у `FemboyLauncher-Portable-<версия>.exe` данные (сборки, миры, Java, настройки) лежат в папке `data` рядом с exe, так что всё можно унести на другой компьютер. Для обычного exe это включается пустым файлом `portable.txt` рядом с ним. Если у человека уже были данные в профиле Windows, а папки `data` ещё нет, они молча не переезжают (иначе «пропали» бы все сборки): лаунчер остаётся на прежнем месте и в Настройках → О лаунчере подсказывает, как перенести. Не получилось записать рядом с программой (например, `Program Files`) — работает как обычно.
- **Кнопка «Отменить»** рядом с полосой загрузки: мгновенно прерывает подготовку запуска (Java, файлы игры, установщик Forge), установку модов и модпаков, оптимизацию, перенос сборок; недокачанные файлы удаляются.
- **Файл настроек под защитой**: `launcher.json` пишется «целиком или никак» (через временный файл), раз в 15 минут и при запуске делается копия `launcher.json.bak`. Если файл оказался испорчен, лаунчер откладывает его рядом (`launcher.json.damaged-…`), возвращает аккаунты и настройки из копии и сообщает об этом, а не молча начинает с нуля. Так же пишутся `instance.json` сборок и метаданные модов.
- **Один лаунчер и ярлыки сборок**: второй запуск (двойной клик по значку, ярлык) не открывает второе окно, а показывает уже открытое: два окна с одними данными затирали бы настройки друг друга. Кнопка **«Ярлык на рабочий стол»** (окно сборки → Ещё) кладёт на рабочий стол ярлык, который запускает именно эту сборку; если лаунчер уже открыт, игра стартует в нём. То же из командной строки или скрипта: `"Femboy Launcher.exe" --launch=<id сборки> [--world=<папка мира>] [--server=<адрес[:порт]>]` (id сборки — имя её папки в `instances/`; мир и сервер необязательны, а мусор вместо них просто отбрасывается). Игру, которая уже идёт, ярлык не закрывает.
- **Индикатор связи**: точка в заголовке окна. Зелёная — всё отвечает, оранжевая — часть серверов молчит (подсказка называет какие), красная — связи нет, серая — судить пока не по чему. Лаунчер ради неё в сеть не ходит: состояние складывается из итогов настоящих запросов за последние 10 минут (нажатая «Отменить» и обращения к своему компьютеру не в счёт). Клик по точке открывает «Проверить связь».
- **Лог лаунчера**: `logs/launcher.log` в папке данных (версия, ход запуска, ошибки, смена состояния связи; файл до 2 МБ, хранятся три последних; пароли, токены, почта и имя пользователя Windows вычищаются). Открывается из Настроек → О лаунчере и входит в отчёт для поддержки. Неожиданная ошибка не показывает сырое окно Electron «A JavaScript error occurred»: лаунчер записывает её в лог и предлагает «Собрать отчёт», «Продолжить» или «Закрыть лаунчер»; если упал процесс окна интерфейса, окно перезагружается само (не чаще раза в 20 секунд).
- **Зависимости одной кнопкой**: ванильная сборка сама переходит на нужный загрузчик; шейдерам ставится Iris/Oculus (с проверкой, что он есть под версию); ресурспакам — моды для OptiFine-форматов (EMF/ETF, Continuity, CIT Resewn). Версии зависимостей подбираются по требованиям из самого мода (как в Prism), а зависимости, указанные только внутри jar, ищутся на Modrinth.
- **Обновление модпаков** (Modrinth и CurseForge): миры, свои моды, options.txt и серверы остаются, файлы модпака заменяются.
- **Перетаскивание файлов** в окно: .jar — мод, .zip — ресурспак/шейдер/модпак (по содержимому), .mrpack — модпак, папка Prism — сборка, .png — скин.
- **Поиск, группы и сортировка сборок.**
- **Темы «Сакура» (с лепестками) и «Полночь»**, свой цвет акцента; анимации — включены, как в Windows или выключены.
- **Котик**: фразы по времени суток, напоминание отдохнуть после 2 часов игры, праздничные наряды (Хэллоуин, Новый год, День святого Валентина), свои фразы.
- **Место на диске** (Настройки): сколько занимают Java, версии, библиотеки и ресурсы игры, и очистка всего, что не нужно ни одной сборке. Сборки, миры и моды очистка не трогает; удалённое лаунчер скачает заново, если понадобится. Отдельной строкой («Старые логи игры») показываются логи, отчёты о вылетах и `hs_err` в общей папке игры: они остались от версий лаунчера, где Java запускалась оттуда, у каждой сборки теперь свои логи, а эти никому не нужны (логи сборок и лаунчера не затрагиваются; такой строки нет, если старых логов нет).
- **Одинаковые моды** (Настройки → «Место на диске»): «Найти одинаковые моды» сверяет моды всех сборок по размеру и хэшу и показывает, сколько места освободится; «Объединить» делает из одинаковых файлов один (жёсткие ссылки): имена, включённость и содержимое в сборках остаются прежними. Только по кнопке, только `mods/*.jar` (и `.jar.disabled`), файлы мельче 1 КБ не трогаются; у сборок с идущей игрой моды пропускаются, не вышло (файл занят, другой диск) — файл остаётся как был. Загрузка, установка и перетаскивание мода поверх общего файла сначала отделяют его (`fsx.breakLink`), так что обновление мода в одной сборке не меняет его в другой. Если заменить такой файл вручную прямо поверх, он изменится во всех сборках: в окне это написано.
- **Котик**: аксессуары (бантик, наушники, шапочка), засыпает, если долго ничего не трогать, сердечки при успехах. Свой фон из картинки с прозрачностью и размытием. Значок в трее, пока лаунчер спрятан на время игры. Мастер первого запуска.
- **Вход через Microsoft** (лицензия), **Ely.by** и **оффлайн** (только ник). Для лицензии можно менять скин и плащ прямо из лаунчера.
- **Скины для оффлайн-аккаунтов**: 3D-превью, загрузка PNG, скин любого игрока по нику (Mojang → Ely.by), пресеты и пиксельный редактор (карандаш, ластик, заливка грани, пипетка, слои, Classic/Slim, отмена). В игре скин подключается через authlib-injector и локальный сервер скинов (только 127.0.0.1), так же как в HMCL. Скин видишь ты сам; другие игроки на сервере увидят его, только если там стоит SkinsRestorer или похожий плагин.
- **Автозагрузка Java** нужной версии (8 / 17 / 21…).
- Темы: светлая, тёмная или как в системе; четыре цвета акцента.
- **Проверка сборки перед запуском**: лаунчер читает описания модов (fabric.mod.json, quilt.mod.json, mods.toml) и до запуска показывает несовместимые моды, недостающие зависимости, неподходящие версии и дубли. Недостающее ставится одной кнопкой, лишний мод выключается кнопкой. Мод, который сам объявляет себя несовместимым с уже стоящим, не устанавливается вовсе (ни из каталога, ни перетаскиванием).
- **Английский язык** (Настройки → Оформление → Язык / Language). По умолчанию интерфейс русский.
- **Активность в Discord**: «Играет в Femboy Launcher» с названием сборки, версией, загрузчиком, сервером и временем в игре. В Настройках её можно выключить или скрыть адрес сервера. Работает через программу Discord на компьютере, без входа.

# 🛠️ Для разработчика

## Discord-активность: настройка

1. На discord.com/developers/applications создай приложение **Femboy Launcher** и скопируй **Application ID**.
2. В `package.json` впиши его в `discord.clientId`; по желанию — до двух кнопок в `discord.buttons` (`{ "label": "Скачать", "url": "https://…" }`).
3. В разделе **Rich Presence → Art Assets** загрузи картинки из папки `discord-assets` с именами `logo`, `fabric`, `quilt`, `forge`, `neoforge`, `vanilla`.
4. Пересобери лаунчер. Пока `clientId` пустой, активность выключена и лаунчер ничего не делает.

## Как поделиться лаунчером

Другим людям ничего ставить не нужно: ни Node.js, ни Java. Дай ссылку **https://femboylauncher.ru/#download**: там актуальный выпуск и помощь с первым запуском. Также можно передать один файл из папки `dist` (после `build.bat`) или `dist-release` (после `release.bat`), либо ссылку на публичную папку Яндекс.Диска:

- **`FemboyLauncher-Setup-<версия>.exe`** — обычный установщик: выбор папки, ярлыки на рабочем столе и в «Пуске», удаление через «Приложения» Windows. Миры, сборки и аккаунты при удалении сохраняются.
- **`FemboyLauncher-Portable-<версия>.exe`** — один файл без установки, просто запускается (например, с флешки).

Java, файлы игры, Forge/NeoForge и моды лаунчер скачивает сам при первом запуске сборки.

Файлы не подписаны цифровой подписью (сертификат платный), поэтому при первом запуске Windows может показать «Windows защитил ваш компьютер» → **Подробнее** → **Выполнить в любом случае**.

## Автообновление и выпуск (Cloud + резерв Диск)

Установленная Setup-версия проверяет обновления при запуске и каждые 2 часа через generic HTTPS источник из package.json updates.url: https://downloads.femboylauncher.ru/. Скачивается полный Setup без дифференциальной blockmap-загрузки. Новая версия загружается в фоне, заметки доступны в «Что нового», установка по кнопке или при закрытии; во время игры перезапуск не предлагается. Portable только сообщает о новой версии и открывает раздел скачивания сайта. Старые установленные версии знают Диск; при API 429 опубликована [помощь](https://femboylauncher.ru/#help-update-429) для ручного перехода с сохранением данных. Пользователь подтвердил полное автообновление 0.10.1 → 0.10.2.

Новый выпуск — только по явному запросу. Версия обновляется согласованно в package.json/lock, RU/EN запись whatsnew.js переносится через build/release-notes.js в releaseNotes/latest.yml. Настоящий release.bat запускает пользователь. Порядок: npm test → проверка доступа S3 → сборка Setup/Portable/latest.yml → публикация обоих EXE в Cloud → полные публичные SHA256 → latest.yml → проверка/retention → резерв Яндекс.Диск → локальная очистка → сведения/двуязычная история и сборка сайта → Firebase Hosting проекта femboy-launcher.

Нужны настроенные локальные S3 credentials, работающий резерв Диска и Firebase CLI/login; ключи не печатать/не копировать. EXE одного номера неизменяемы. В Cloud хранятся текущая и предыдущая полные пары; правила удаления ограничены файлами выпуска, чужие/новые не затрагиваются. Локальные старые установщики чистит build/clean-dist.js после успешной публикации.

Если Диск завершился ошибкой после Cloud, основной выпуск уже опубликован. Если сайт не собрался/не выложился, EXE остаётся выпущенным, старый dist не публикуется. Повторять только нужный шаг после выяснения причины, не пересобирать тот же номер наугад. Подробности [docs/object-storage-updates.md](docs/object-storage-updates.md) и актуальный CURRENT_STATE.md. Пробная сборка для проверки — отдельная папка и --publish never, не release.bat.

**Чистка:** `dist-release/` копил бы установщики всех выпусков, по 150 МБ на версию, поэтому после удачной выкладки `release.bat` сам запускает `build/clean-dist.js`: он убирает установщики (Setup, Portable и `.blockmap`) всех версий, кроме текущей. Остаются текущая версия, `latest.yml`, `win-unpacked` (с ним сверяют состав новой сборки перед следующим выпуском) и всё, что скрипт не знает; прошлая версия лежит в `archive` на Диске. Нет файлов текущей версии — скрипт ничего не удаляет, а сбой чистки выпуск не останавливает. Посмотреть, что будет убрано, ничего не удаляя: `node build/clean-dist.js dist-release --dry-run`.

Основная раздача через GitHub сейчас не используется: скачивание на сайте работает через Cloud, Яндекс.Диск остаётся резервом. Если задать переменную `GH_TOKEN`, `release.bat` дополнительно создаст на GitHub черновик релиза (настройки `build.publish` и `updates.github` остались в `package.json`).

## Сборка установщика

Дважды кликни **`build.bat`**: соберёт оба файла в `dist/` (инструменты сборки качаются с зеркала npmmirror, потому что GitHub бывает недоступен). Перед новой раздачей подними `version` в `package.json`. Лишние языки Chromium в сборку не попадают (`electronLanguages` в `package.json`: остаются русский и английский). `release.bat` собирает в отдельную папку `dist-release/`, чтобы лаунчер, запущенный из `dist/`, не мешал сборке.

Картинки установщика рисуются из `build/art/installer-art.js` тем же котиком и пейзажем, что в лаунчере. Поменял что-то в них — запусти `npx electron build/art/render.js`, и в `build/` обновятся три `.bmp` (`--png=папка` положит туда ещё и увеличенные PNG для просмотра).

## Запуск из исходников (для разработки)

1. Установи **Node.js LTS**: https://nodejs.org
2. Дважды кликни **`start.bat`**.

Если `npm install` зависает на скачивании Electron, в проекте уже есть `.npmrc` с зеркалом npmmirror.

Лаунчер один на одни данные, поэтому если уже открыт установленный (или другой запуск из исходников), `npm start` молча завершится: он покажет то окно. Для отдельной проверки укажи другую папку данных: `npx electron . --user-data-dir=C:\temp\fl-test` (по ней же считается «один экземпляр»).

### Тесты

```
npm test              # быстрые проверки на обычном Node (нужен Node 22 или новее), без интернета, около 3 секунд
npm run test:electron # проверки, которым нужен настоящий Electron: сеть через прокси, вход Microsoft, форма-загрузка, ярлык сборки, «Проверить связь», чтение PNG итогов, полоска и список переходов на значке
npm run test:electron-node # те же быстрые проверки, но на Node самого Electron (он старше и на Windows ведёт себя по-своему)
npm run test:ui       # интерфейс в настоящем Электроне: лаунчер из исходников на временном профиле, все окна и функции по очереди (около двух–трёх минут, на это время открывается окно; в npm test и release.bat не входит)
```

В `tests/` лежат проверки точек восстановления, входа через Ely.by (против поддельного сервера, настоящих паролей и обращений к ely.by нет), выбора Java, происхождения модов, отчёта и очистки логов, отправки на mclo.gs (тоже поддельный сервер), portable, защиты `launcher.json`, работы без интернета, сетевого слоя с отменой и состояния связи, переноса сборки на новую версию (подменённые Modrinth и CurseForge), поиска мода-виновника (алгоритм на случайных сборках и состояние на диске), списков версий загрузчиков, аргументов командной строки, лога лаунчера и обработчика неожиданных ошибок. Настоящий интернет им не нужен: `tests/helpers.js` подменяет `fetch`. Отдельно `tests/renderer-order.test.js` стережёт порядок файлов интерфейса: что `index.html` подключает все файлы `src/renderer/app/` (core первым, start последним), что имена не повторяются и что файлы запускаются по порядку в пустом окне-заглушке без ошибок. Если при добавлении кода он говорит «X is not defined», значит файл при загрузке зовёт то, что объявлено ниже по списку: перенеси вызов в обработчик или подними файл с X выше.

## Где лежат файлы

`%APPDATA%\Femboy Launcher\` (у portable-версии это папка `data` рядом с exe), данные из старого Sugarcube Launcher переносятся туда автоматически:
- `minecraft/`: общие версии, библиотеки и ассеты
- `instances/<id>/.minecraft/`: папка сборки (`mods/`, `saves/`, `config/`…)
- `java/`: скачанные Java
- `launcher.json`: аккаунты и настройки
- `readiness.json`: итоги фонового подсчёта «готово ли к новой версии» по сборкам (можно удалить: пересчитается)
- `modwatch.json`: итоги фоновой проверки «вышли ли обновления модов» по сборкам: сколько и какие (можно удалить: пересчитается)
- `trash/`: корзина удалённых сборок (очищается, когда лаунчер закрывается)
- `playlog.json`: журнал игровых сессий для «Времени в игре»
- `logs/launcher.log`: лог лаунчера (до 2 МБ, три последних файла)

## Структура кода

- `src/main.js`: главный процесс Electron, IPC (новый канал или событие нужно вписать и в `src/preload.js`; что названия сходятся, сверяет `tests/ipc-channels.test.js`)
- `src/core/accounts.js`: Microsoft (msmc) и оффлайн-аккаунты
- `src/core/game.js`: запуск игры (minecraft-launcher-core)
- `src/core/modrinth.js`, `src/core/curseforge.js`: поиск и установка модов и модпаков
- `src/core/mods.js`: установленные моды сборки
- `src/core/versions.js`: версии Mojang, Fabric и Quilt
- `src/core/forge.js`: установка Forge и NeoForge официальным установщиком
- `src/core/skins.js`, `src/core/yggdrasil.js`: скины оффлайн-аккаунтов и локальный сервер скинов
- `src/renderer/skin-editor.js`: 3D-превью и редактор скинов (skinview3d)
- `src/core/java.js`, `src/core/instances.js`
- `src/core/net.js`: сеть: стек Chromium (системный прокси) с запасным путём, таймауты, повторы, зеркала, загрузки с проверкой хэша и **отмена** (область отмены на `AsyncLocalStorage`: `runCancellable`, `throwIfCancelled`, `pool`)
- `src/core/proxy.js`: прокси из настроек и для игры (флаги Java); `src/core/netcheck.js`: «Проверить связь»
- `src/core/updater.js`: автообновление через electron-updater (проверка при запуске и раз в 2 часа, portable только сообщает о новой версии); `src/core/yandex-updates.js`: свой поставщик обновлений, читает `latest.yml` и файлы версии из публичной папки Яндекс.Диска (ссылка в `updates.yandex` файла `package.json`)
- `release.bat`, `build/publish-yandex.ps1`, `build/release-notes.js`, `build/clean-dist.js`: выпуск (тесты → заметки → сборка в `dist-release/` → выкладка на Диск → прошлая версия в `archive` → чистка старых установщиков в `dist-release/`), порядок шагов в разделе «Автообновление и выпуск»; проверки чистки лежат в `tests/clean-dist.test.js`
- `src/core/e4mc.js`: разбор лога игры для «Играть с другом»: адрес мира от мода e4mc и его ошибки
- `src/core/modcode.js`: «Код сборки» и «Войти к другу»: формат кода (`pack` / `unpack`: длина в заголовке, защита от «бомб» и мусора), разбор сообщения друга (`parseInvite`: адрес и код в любом тексте), код своих модов (`encode`), сверка с чужим кодом (`compare`) и установка точных версий (`apply` / `join`, в том числе в новую сборку «как у друга»); Modrinth в тестах подменён (`tests/modcode.test.js`). Окно и кнопки хозяина: `src/renderer/app/join.js`
- `src/core/friendcheck.js`: «Проверка игры с другом»: коды результатов (моды, путь в сеть, сервер e4mc, UDP до ретранслятора, белый список), сеть подменяется в тестах; тексты к кодам лежат в `src/renderer/app/friends.js`, а `tests/friendcheck-texts.test.js` сверяет их с кодами
- `src/core/netprobe.js`: пробы сети «как это сделает игра»: HTTPS напрямую и через туннель HTTP-прокси (CONNECT), один QUIC-пакет по UDP
- `src/core/lansession.js`: жизнь мира, открытого для друзей, по строкам лога игры; за ним очищается белый список (`friendlist.clear`)
- `src/core/mods.js`, `src/core/modupdates.js`: файлы сборки (включение, закрепление версии, метаданные) и проверка обновлений (закреплённые моды не проверяются): полная `check` (с докачкой и сверкой совместимости, приносит «Что нового») и лёгкая `lookup` для фона; `plainChangelog` делает из описания версии простой текст
- `src/core/modwatch.js`: значок «вышли обновления модов»: фоновый обход раз в сутки (`sweep` / `start`), итог в `modwatch.json` (`check` / `record` / `get`, сбрасывается по `snapshots.modsSig`); Modrinth в тестах подменён (`tests/modwatch.test.js`). Значок, окно и выключатель: `src/renderer/app/home.js`, `mods.js`, `settings.js`
- `src/core/collection.js`: импорт коллекции Modrinth: `parseLink` (ссылка на коллекцию в любом тексте), `load` / `loadById` (сама коллекция из API v3 и её проекты из v2 пачками по сто, в памяти десять минут), `compat` («подходит ли» под версию игры и загрузчик), `suggest` (что предложить для новой сборки), `show` / `fits` (ответы окну: коллекция с советом и пометки под выбранную цель), `run` (установка выбранного: точка восстановления, новая сборка, отмена); Modrinth в тестах подменён (`tests/collection.test.js`). Окно: `src/renderer/app/collection.js`
- `src/core/taskbar.js`: полоска прогресса на значке в панели задач: решает, что показывать (последнее обновившееся дело, проценты до целых, повторы не шлёт); само окно подставляет `main.js` (`setProgressBar`); `tests/taskbar.test.js`
- `src/core/jumplist.js`: список переходов на значке: `build` (последние сборки → ссылки `--launch=<id>`), `asTasks` (запасной вид для Windows без «недавних элементов»), `enabled` (только установленная и portable) и `scheduler` (обновление после затишья, одинаковый список второй раз не шлётся); `tests/jumplist.test.js`; что Windows принимает список, проверяет `npm run test:electron` под своим идентификатором программы
- `src/renderer/updatenotes.js`: заметки об обновлении: сборка делает из записи «Что нового» markdown для `latest.yml` (`render`), лаунчер читает его обратно (`parse`); один файл и для Node, и для окна; `build/release-notes.js` запускает `release.bat`
- `src/core/worlds.js`: миры и скриншоты сборки: список, резервные копии и автокопии (после игры и перед открытием мира для друзей: `openedSince`, `backupOpened`), восстановление
- `src/core/playlog.js`: журнал сессий игры (`playlog.json`) и расчёт для «Времени в игре» (неделя по дням, сборки за 30 дней; сессию через полночь делит по дням)
- `src/core/recap.js`: «Итоги игры»: расчёт недели/месяца из журнала (`build`: окно по дням, сравнение с прошлым таким же сроком, любимая сборка, самая долгая игра, лучший день) и готовая карточка с подписями на русском и английском (`describe` / `card`, реплика котика по уровню игры, имя файла `fileName`); в тестах журнал задан вручную (`tests/recap.test.js`). Рисует её `src/renderer/app/recap.js` (холст, окно, кнопки)
- `src/core/imagesave.js`: картинки из окна: `decodePng` пропускает только целый PNG до 16 МБ (подпись, конец файла, base64), `save` спрашивает место (диалог подставляет `main.js`) и пишет файл «целиком или никак»; в буфер обмена (`app:copyImage`) тоже идёт только проверенное (`tests/imagesave.test.js`)
- `src/core/diskspace.js`: свободное место на диске и понятная ошибка «не хватает места» перед загрузками (`gamefiles`, клиент игры в `versions`)
- `src/core/gamefiles.js`: докачка библиотек и ресурсов перед запуском (хэш библиотек, наличие и размер ресурсов; с `deep` — хэш всех ресурсов), отвечает, сколько проверено и перекачано; `src/core/repair.js`: «Починить файлы игры» поверх неё
- `src/core/storage.js`: место на диске: что не нужно ни одной сборке (Java, версии, библиотеки, ресурсы, установщики, старые логи в общей папке игры) и очистка этого
- `src/core/dedupe.js`: «Одинаковые моды»: `scan` (подсчёт по размеру и хэшу, сколько освободится) и `apply` (жёсткая ссылка под временным именем и подмена файла целиком; занятые сборки и неудачи пропускаются); `fsx.breakLink` отделяет общий файл перед записью поверх; `tests/dedupe.test.js`. Окно: блок в Настройках (`app/settings.js`)
- `src/core/lanaddress.js`: адреса для входа напрямую по сети и VPN (`candidates`) и порт открытого мира из лога (`watcher`); таблицу адаптеров для проверок подменяет переменная `FEMBOY_TEST_INTERFACES`
- `src/core/gamelog.js`: что открывают кнопки «Лог игры» / «Папка логов» (путь решает эта функция, а не окно; нет файла — понятное сообщение)
- `src/core/lanplayers.js`: кто из друзей сейчас в открытом мире, по строкам лога игры («joined the game» / «left the game»; первый зашедший — хозяин)
- `src/core/trash.js`: корзина сборок: перенос в `trash\`, возврат, окончательное удаление, очистка при закрытии лаунчера
- `src/core/friendlist.js`: белый список друзей: `whitelist.json` с верным UUID (игра считает UUID от ника с учётом регистра, а `/whitelist add` — от ника строчными); другу с лицензией пишется ещё настоящий UUID
- `src/core/friends.js`: общий список друзей (в `launcher.json`): ник, «без лицензии», UUID настоящего аккаунта (его один раз спрашивают у Mojang), галочка «пустить в этот мир»; перенос старых ников из окон сборок
- `src/core/migrate.js`: перенос сборки на новую версию Minecraft (план по хэшам модов, потом копия сборки с откатом при сбое; `quick` — лёгкий подсчёт для значка «пора на новую версию?»)
- `src/core/readiness.js`: значок «пора на новую версию?»: фоновый обход раз в сутки (`sweep` / `start`), итог в `readiness.json` (`check` / `get`, сбрасывается по `snapshots.modsSig`); Modrinth и список версий в тестах подменены (`tests/readiness.test.js`). Значок и выключатель: `src/renderer/app/home.js`, `settings.js`
- `src/core/loaders.js`: списки версий Fabric/Quilt/Forge/NeoForge под игру (порядок версий, «последняя», кэш на 10 минут) и проверка модов под выбранную версию загрузчика
- `src/core/bisect.js`: поиск мода-виновника (алгоритм: игра без модов → деление пополам → проверка найденного → при необходимости ddmin для сочетаний; состояние в `bisect.json`), окно — `src/renderer/bisect.js` (подключается до `app/`)
- `src/core/snapshots.js`: точки восстановления сборки и особая точка «Последний удачный запуск» (`markGood`, `sinceGood`, `modsSig`; когда её делать, решает `src/core/game.js` в обработчике закрытия игры); `src/core/origins.js`: откуда моды (Modrinth по хэшу)
- `src/core/elyby.js`: вход через Ely.by (протокол Yggdrasil) и аргументы authlib-injector; `src/core/javafind.js`: поиск и проверка Java
- `src/core/scrub.js`: очистка текста от токенов, путей с именем пользователя, почты и адресов; `src/core/report.js`: отчёт для поддержки; `src/core/mclogs.js`: отправка лога на mclo.gs
- `src/core/portable.js`: где лежат данные portable-версии; `src/renderer/palette.js`: быстрый поиск Ctrl+K
- `src/core/cli.js`: аргументы командной строки (`--launch`, `--world`, `--server`; `pack` — полный путь к `.mrpack`, который передаёт Проводник; привязка типа файла — `build.fileAssociations` в `package.json`, вопрос и импорт — `takePackRequest` в `app/import.js`); `src/core/shortcut.js`: ярлык сборки на рабочий стол; в `src/main.js` же «один экземпляр» (`requestSingleInstanceLock`)
- `src/core/logger.js`: лог лаунчера с ротацией и очисткой; `src/core/fatal.js`: что делать с неожиданной ошибкой главного процесса (лог, окно, не чаще раза в полминуты)
- `tests/`: проверки (`npm test`); `tests/electron/`: проверки в Электроне (`npm run test:electron`); `tests/ui/`: дымовая проверка окон и функций интерфейса (`npm run test:ui`: профиль собирается кодом лаунчера, список проверок в `checks.js`; `UI_ONLY=часть названия` гоняет только такие проверки, несколько через `|`)
- `src/core/fsx.js`: запись файлов «целиком или никак», чтение JSON с повтором и копией `.bak`; на нём `store.js` (`launcher.json`), `instances.js`, `mods.js`
- `src/core/otherlaunchers.js`: поиск других лаунчеров (известных и по устройству папок), перенос и освобождение места
- `src/core/gpu.js`: мощная видеокарта для Java в «Параметрах графики» Windows
- `src/core/optimize.js`: набор модов для скорости под загрузчик и версию; `src/core/graphics.js`: профили графики в `options.txt`; `src/core/speed.js`: советы по скорости
- `src/renderer/`: интерфейс (`cat.js` — бойкиссер, `scenes.js` — пейзажи карточки сборки, `calm.js` — сон анимаций, `theme.js` — тема без мигания)
- `src/renderer/app/`: основной код интерфейса, разрезанный по темам (раньше один `app.js`): `core.js` (состояние, вызовы главного процесса, помощники), `look.js` (тема, фон, курсоры), `shell.js` (навигация, маскот), `home.js` (полка сборок и главная), `modals.js`, `import.js`, `details.js`, `migrate.js`, `mods.js`, `accounts.js`, `settings.js`, `launch.js`, `events.js`, `start.js` и другие; о чём каждый файл — в его первой строке. Это обычные скрипты с общей областью видимости, а не модули: порядок подключения задаёт `index.html` (`core.js` первым, `start.js` последним). Правило одно: то, что выполняется сразу при загрузке файла, не должно вызывать функции из файлов ниже по списку (их ещё нет); из обработчиков и функций, которые вызываются позже, можно обращаться к любым (правило проверяет `tests/renderer-order.test.js`)
- `src/renderer/fonts/`: шрифты Comfortaa, Fredoka и Nunito (лицензия OFL, текст в `LICENSE-fonts.txt`)
