Актуально 9 ноября 2026: опубликованы 0.10.2 и RU/EN сайт. Сначала [../CURRENT_STATE.md](../CURRENT_STATE.md), [CLAUDE.md](CLAUDE.md) и [передача полного аудита](../docs/AUDIT-HANDOFF-2026-11-09.md). HANDOFF-2026-11-08.md содержит историю, а не текущую схему загрузок.

связь с выпуском лаунчера, проверки, поисковики и незавершённое подключение домена. Инструкции для Claude — в [CLAUDE.md](CLAUDE.md).

Статическая главная: что умеет лаунчер, настоящие скриншоты, темы «Сакура» и «Полночь», шаги начала, скачивание, помощь и вопросы.

Сделан на [Astro](https://astro.build) 5. Сервер, база данных и сбор данных о посетителях не нужны: сборка — обычная папка файлов,

`release.bat` автоматически обновляет сведения о выпуске и собирает сайт. После успешной сборки он автоматически публикует сайт в Firebase Hosting.

## Запуск и сборка

В package.json заявлен Node.js >=20.3; последняя успешная сборка выполнена Node 24.22.1. Совместимость фактического нового синтаксиса перевода с нижней заявленной версией включена в аудит и пока не подтверждена.

```
npm install          # один раз
npm run dev          # сайт для правок: http://127.0.0.1:4321, изменения видны сразу
npm run build        # проверки конфига скачивания + сборка в папку dist/
npm run preview      # посмотреть готовую сборку из dist/ на http://127.0.0.1:4321
npm run check:config # только проверки конфига скачивания (tests/)
npm run sync:release # восстановить сведения из dist-release после уже успешной публикации лаунчера
```

`npm run build` сначала гоняет тесты из `tests/`: если в `src/config/downloads.json` что-то не так, сборка остановится.
Мелкие огрехи (например, кривая дата) сборку не останавливают: такое значение просто не показывается, а в выводе сборки
появляется строка `[downloads.json] …`.

**Готовая сборка лежит в `dist/`.** Это и есть сайт: `index.html`, `releases/index.html`, `404.html`, картинки, шрифты, `robots.txt`, `sitemap.xml`.
Для размещения нужна только эта папка.

## Версия и адреса установщиков

Всё о скачивании — в одном файле `src/config/downloads.json`. Компоненты сами адресов не знают.

```json
{
  "release": {
    "version": "0.10.0",
    "date": "2026-11-03",
    "highlights": ["…что нового, по строке на пункт…"]
  },
  "storage": {
    "provider": "yandex",
    "label": "Яндекс.Диск",
    "where": "на Яндекс.Диске",
    "folderUrl": "https://disk.yandex.ru/d/…",
    "fileUrlTemplate": ""
  },
  "files": {
    "setup":    { "fileName": "FemboyLauncher-Setup-{version}.exe",    "url": "", "sizeBytes": 77115168, "sha256": "…" },
    "portable": { "fileName": "FemboyLauncher-Portable-{version}.exe", "url": "", "sizeBytes": 76869229, "sha256": "…" }
  }
}
```

- `release.version` — опубликованная версия (как в `package.json` лаунчера), `release.date` — день выпуска `ГГГГ-ММ-ДД`.
  Дата берётся из `releaseDate` в `latest.yml` выпуска, а не из сегодняшнего дня.
- `release.highlights` — короткий список «Что нового» в разделе скачивания. Пустой список — блок не показывается.
- `files.*.fileName` — имя файла; `{version}` заменяется версией.
- `files.*.sizeBytes` и `files.*.sha256` — необязательны. Пустое или неверное значение просто не показывается.
  Узнать: `Get-FileHash .\FemboyLauncher-Setup-X.exe` (SHA-256) и размер файла в байтах.

**Откуда кнопка берёт адрес** (по порядку):

1. `files.<setup|portable>.url` — полный постоянный адрес именно этого файла (`https://…`);
2. `storage.fileUrlTemplate` — шаблон адреса, например `https://files.example.org/launcher/{fileName}`:
   в него подставляются `{fileName}` и `{version}`;
3. при `storage.provider: "yandex"` сайт при нажатии получает свежую ссылку на конкретный файл через публичный API
   Яндекс.Диска и передаёт её браузеру; ключи и вход в аккаунт не нужны;
4. иначе прямой ссылки нет, и кнопка честно называется «Открыть файлы на Яндекс.Диске» и ведёт в общую папку
   `storage.folderUrl` (в новой вкладке, с подсказкой, какой файл там выбрать).

Как только у файла есть прямой адрес, кнопка сама становится «Скачать установщик» / «Скачать Portable», а пояснение
про папку исчезает. Принимаются только адреса `https://`.

**Основные кнопки сейчас используют постоянные HTTPS-ссылки Cloud** из storage.fileUrlTemplate. Яндекс.Диск — запасная папка. Следующее описание относится к сохранённой API-логике для storage.provider="yandex": ссылки временные, поэтому запрашиваются заново при каждом нажатии.
Файлы должны лежать в корне `storage.folderUrl` под именами из конфига. При ошибке сети, ограничениях Яндекса
или блокировке запроса браузером показывается сообщение и остаётся запасная ссылка на папку.
Ожидание ограничено 15 секундами. Без JavaScript доступна ссылка на папку. Успех получения ссылки не означает,
что файл уже сохранён: завершение скачивания проверяют в самом браузере.

Переход к файлу выполняется ссылкой с `referrerPolicy="no-referrer"` и `rel="noreferrer"`.
Важно сохранить эту настройку: `window.location.assign()` передавал адрес сайта в `Referer`,
и сервер скачивания Яндекса отклонял запрос (в Chromium — `ERR_INVALID_RESPONSE`).
Настройка `referrerPolicy` у запроса API сама по себе не распространяется на последующий переход.
Исправление проверено Chromium на домене сайта с подстановкой локального скрипта:
обе кнопки скачали полные файлы 0.10.0, размеры и SHA-256 совпали с конфигом.

Перед публикацией проверь основные прямые Cloud-кнопки и запасную папку. Если менялась legacy API-логика Диска, дополнительно проверь обе кнопки с реальным API: модульные тесты проверяют ответы-заглушки,
но не доступность Яндекс.Диска и разрешение запросов с домена сайта (CORS). Временный адрес `href` в конфиг не вставляй.

**При новом выпуске лаунчера** редактировать эти поля вручную больше не нужно. После успешной выкладки в Cloud и на резерв Диска
`release.bat` запускает `node build/website-release.js dist-release --build` из корня проекта. Этот шаг:

1. Сверяет версию в `latest.yml` и `package.json`, наличие обоих непустых установщиков, размер и SHA-512 установщика по манифесту.
2. Берёт дату из `releaseDate`, вычисляет SHA-256 и размеры обоих файлов, обновляет `downloads.json` одной атомарной записью.
3. Для новой версии берёт заголовки русского «Что нового» из `releaseNotes` готового выпуска. Нет заметок — список пустой;
   пункты прошлого выпуска не переносятся. При повторной подготовке той же версии сохраняются короткие отредактированные пункты сайта.
4. Запускает тесты сайта и сборку в `website/dist`.

Настройки Яндекс.Диска, шаблон адреса и остальные настройки сохраняются. Фиксированные адреса файлов при смене версии
требуют ручной проверки: скрипт остановится вместо сохранения ссылки на старый файл.
Если проверка входных файлов не прошла, `downloads.json` остаётся целиком прежним. Ошибка подготовки сайта отмечается
предупреждением в окне выпуска, но уже опубликованный лаунчер она не отменяет. В этом случае старый `dist` публиковать нельзя.

У сайта должны быть установлены свои зависимости (`npm install` внутри `website`, один раз).
После успешного шага release.bat вызывает build/deploy-website.bat: сайт публикуется в существующий Firebase Hosting проекта femboy-launcher.
Обычный `npm run build` не считывает черновую сборку лаунчера: он собирает сайт по сохранённому конфигу.

Для проверки без записи из корня лаунчера: `node build/website-release.js dist-release --dry-run`.
Для повторной подготовки сайта после уже успешного выпуска: `node build/website-release.js dist-release --build`.

## История версий

Страница `/releases/` использует сохранённый `src/data/releases.json`, поэтому сайт собирается самостоятельно,
без исходников лаунчера на хостинге. Ссылки на историю находятся под «Что нового» на главной и в подвале;
обе страницы включены в Sitemap. По ссылке вида `/releases/#release-0-8-4` нужная запись раскрывается автоматически.

После успешной публикации лаунчера `build/website-release.js` обновляет также историю через `build/website-history.js`:
берёт русские и английские записи из `src/renderer/whatsnew.js` (items и itemsEn), отсекает версии новее опубликованной и сортирует по номерам версий.
У текущего выпуска приоритет у заметок и даты из проверенного `latest.yml`. Уже сохранённые старые выпуски сохраняются,
даже если их позднее уберут из журнала лаунчера. Неизвестные даты не выдумываются, известные сохраняются.
При обычной правке сайта и `npm run build` черновики лаунчера в историю не импортируются.

## Как сменить хранилище установщиков

Интерфейс менять не нужно, только `src/config/downloads.json`:

- файлы лежат по постоянным адресам с одинаковым началом → впиши `storage.fileUrlTemplate`;
- у каждого файла свой адрес → впиши `files.setup.url` и `files.portable.url`;
- поменяй `storage.label` и `storage.where` («на …»), если хранилище называется иначе;
- при переходе с Яндекс.Диска убери `storage.provider` или задай пустую строку;
- `storage.folderUrl` — запасная страница со всеми файлами. Если её нет, оставь пустой строкой: при прямых адресах она не нужна.

Скачивание по прямой ссылке начинается по нажатию кнопки. Сохранится ли файл сразу или браузер сначала откроет его,
решают заголовки хранилища (`Content-Disposition`), сайт на это не влияет.

Автообновление установленной 0.10.2 использует generic HTTPS downloads.femboylauncher.ru (updates.url в package.json), независимо от страницы сайта. Диск сохранён для старых конфигов/версий; Portable открывает страницу скачивания.

## Адрес сайта (домен)

Основной адрес сайта: **https://femboylauncher.ru**. Резервный адрес Firebase: https://femboy-launcher.web.app/. Основной адрес записан в `src/config/site.json`:

```json
{ "url": "https://femboylauncher.ru" }
```

Из него при сборке получаются каноническая ссылка, `og:url`, полный адрес картинки предпросмотра, `sitemap.xml` и строка
`Sitemap:` в `robots.txt`. При переезде на другой домен поменяй `url` (или задай при сборке переменную `SITE_URL`).
Пустой `url` — страница собирается без канонической ссылки, `og:url` и карты сайта.

## Публикация (Firebase Hosting)

Настройки лежат рядом: `firebase.json` (папка публикации `dist`, без перенаправлений) и `.firebaserc` (проект
`femboy-launcher`). Обновить сайт:

```
npm run build
firebase deploy --only hosting
```

После успешного запуска `release.bat` сайт уже опубликован. Нужны установленный Firebase CLI и действующий вход (`firebase login`). Если сборка сайта или публикация не удалась, батник выводит предупреждение. Повторить только сайт из корня проекта: `node build/website-release.js dist-release --build && build\deploy-website.bat`. Сначала обязательно успешная сборка: старый dist при ошибке не публикуется.

Страница `404.html` из сборки Firebase показывает сам для несуществующих адресов.

Если сайт будет жить не в корне домена, а в подпапке (например, `https://example.org/launcher/`), задай ещё
`BASE_PATH=/launcher/` при сборке — все пути к файлам поправятся сами.

## Русская и английская версии — 9 ноября 2026

Русские адреса сохранены. Английские страницы: /en/, /en/releases/ и обе инструкции под /en/guides/. Переключатель RU / EN открывает ту же страницу и сохраняет hash и query; автоматического перенаправления по языку браузера нет.

Обе версии используют общие Astro-компоненты. src/middleware.ts при предварительной сборке английских страниц переводит текстовые узлы и доступные подписи через src/lib/localize.js и словарь src/data/en.json. На хостинг уходит готовый английский HTML: JavaScript для чтения перевода не нужен. Скрипты, стили, файлы и внешние ссылки не переводятся. Новый непереведённый русский текст останавливает сборку английских страниц, чтобы смешанная версия не публиковалась незаметно. При правке текстов обновляй словарь. Даты, размеры, версии и шаблон сообщения форматируются независимо от номера выпуска.

История хранит английские itemsEn рядом с русскими items в releases.json. build/website-history.js переносит оба языка из whatsnew.js и финального releaseNotes только для опубликованных версий. Новые заголовки текущего выпуска берутся из той же истории; короткий отредактированный русский заголовок сайта требует своего перевода в en.json. Текущая версия лаунчера остаётся 0.10.2.

Canonical и hreflang ru/en/x-default присутствуют на каждой индексируемой странице; sitemap содержит восемь адресов. Английский язык учитывается в ссылке «Поделиться», теме, меню, лайтбоксе, копировании и сообщениях загрузки. Скриншоты и видео настоящие, с русским интерфейсом; это обозначено в английском тексте. Добавлены английские VTT-субтитры, исходный ролик не изменён.

В контактах добавлен личный сайт автора https://bart-awesome.ru/. Telegram и Discord остаются каналами поддержки и отзывов. Личный сайт — отдельный проект, его файлы не менялись.
